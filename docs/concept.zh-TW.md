# 概念

[English](concept.md) | [繁體中文](concept.zh-TW.md)

> 你的時間軸，你寫的規則。沒有 Fediqo 伺服器。

Fediqo 把你讀的東西當成時間軸來管理。它從來源載入 item，依發布時間排開，
並讓你在已經有的東西上加一個 filter，做出新的時間軸。

這一頁是概念：每個詞是什麼意思，以及什麼必須一直成立。它是 Fediqo 要去的地方。
一份 checkout 今天做得到什麼，寫在 [README](../README.zh-TW.md) 的「怎麼用」。

## 四個名詞

| 名詞     | 是什麼                                           |
| -------- | ------------------------------------------------ |
| item     | 帶有發布時間的最小單位                           |
| source   | 被問到時交得出 item，而且能再被問一次的任何來源  |
| filter   | 一條 timeline 讓 item 進來所依的規則             |
| timeline | 輸入加一個 filter，依 item 的發布時間攤平排開    |

## 在哪裡執行

每一件事都發生在你的裝置上。沒有一個 Fediqo 伺服器讓它們經過。
Fediqo 只連到你加入的來源，別的都不連，而且它送出的每一個請求都看得到。

## Item

以下四樣都有，才是 item。

| 它有     | 意思                                         |
| -------- | -------------------------------------------- |
| 發布時間 | 來源自己對這個 item 說的時間，至少到日       |
| ID       | 這個來源上的這個 item 一個；再讀一次還是同一個 |
| 來源     | 它從哪裡來                                   |
| 內容     | 可以顯示的東西，或是對另一個 item 的指向加上是誰做的 |

發布時間是 item 唯一據以排序的時間，而且不會移動。抓到它的那一刻不是它的發布時間；
整頁共用的時間戳不是，最後修改的時間也不是。

item 有兩層，各有一個主人。

| 層         | 放什麼                                 | 誰能改 |
| ---------- | -------------------------------------- | ------ |
| 來源說的   | 內容、欄位，以及每次變動的一個 revision | 來源   |
| 你做的     | keep、已刪除的標記，以及你為它送出過的  | 你     |

### ID

每個來源上的每個 item 有一個 ID。它是穩定的：底下的內容可以變，ID 不變。
它不會再被拿去給別的東西用。item 的一切都掛在它上面——revision、keep、已刪除的標記，
以及它指向什麼。

同一個 item 經過另一條 timeline 讀到時，ID 不變。

### 欄位

| 級別 | 是什麼                          | 規則                                   |
| ---- | ------------------------------- | -------------------------------------- |
| 必備 | 上面那四樣                      | 每個 item 都有                         |
| 通用 | author、category、keyword 等    | 到處都是同一個名字；來源能填的就填     |
| 動態 | 屬於某一個來源的欄位            | 由來源命名，並說出它的型別             |

動態欄位會說出自己是什麼型別：文字、數字、日期、是或否，或一組固定選項中的一個（並列出這些選項）。
filter 就是靠這個知道可以問它什麼。

category 是來源自己對它所提供內容的分法。item 帶著它經由哪些 category 抵達；
category 不是你做的。

## Source

來源彼此可以要多不像就多不像。通過三項檢驗，就是 source。

| 檢驗                           | 擋掉什麼                       |
| ------------------------------ | ------------------------------ |
| 每個 item 有自己的發布時間     | 書的章節、手冊、沒有日期的清單 |
| 每個 item 有穩定的 ID          | item 彼此分不出來的頁面        |
| 可以往下讀——至少讀得到更新的   | 從不說什麼是新的單一頁面       |

某個網路上的帳號、一個論壇、一份 feed、一個分成好幾頁的網頁，在這裡是同一件事：
一段 item，以及問下一段的方法。

每個來源都給得出閱讀。接受一個 act，則是來源可以提供、也可以不提供的事。

## Filter

filter 依 item 的欄位來判斷，三個級別都可以用。規則可以組合。

- item 沒有某條規則問到的欄位時，不符合那條規則。
- 除了這條 timeline 顯示給你看的規則之外，沒有東西會被它留在外面；
  被留在外面的，指得出是哪一條規則。
- 規則所指的東西不見了，規則還在，並且會說出來。

## Timeline

| 它是   | 意思                                                   |
| ------ | ------------------------------------------------------ |
| 組出來的 | 由輸入與一個 filter 組成；輸入是來源，或另一條 timeline |
| 有序的 | 依發布時間，而且只依它；不評分，也不重排               |
| 攤平的 | 每個 item 各自獨立；沒有一個收在另一個底下             |
| 活的   | 它跟著這台裝置留著的東西，輸入一變它就變               |

新的 timeline，就是一條既有的 timeline 加上一個 filter。搜尋是你沒有存下來的 filter。

timeline 顯示的是這台裝置留著的東西。裝置在你要求時、或等候到了時，才去問來源。

## Revision

有三樣東西有 revision。

| 什麼              | 什麼時候前進               |
| ----------------- | -------------------------- |
| item 的內容       | 來源改了它                 |
| timeline 的定義   | 你改了它的輸入或 filter    |
| timeline 的結果   | 它的任何一個輸入前進了     |

來源改了一個 item，那個 ID 就多一個 revision。item 在每一條 timeline 上都留在原位。

## 管理

| Act       | 存在哪裡 | 說明                                     |
| --------- | -------- | ---------------------------------------- |
| 發文      | 來源     | 一個新的 item                            |
| reply     | 來源     | 一個新的 item，指向它所回覆的那個      |
| reblog    | 來源     | 一個新的 item，指向它所 reblog 的那個    |
| favourite | 來源     |                                          |
| bookmark  | 來源     |                                          |
| 收回      | 來源     | 拿回你送出的                             |
| keep      | 這裡     | 任何 item 都能做；keep 的 item 永遠不放下 |

這份清單是開放的。存在來源的 act，只在來源提供時才有；
所以在一個只能讀的來源上，keep 是唯一的 act。

## 放下

| 狀態   | 意思                                                 |
| ------ | ---------------------------------------------------- |
| 留著   | 在它的 timeline 裡                                   |
| 已刪除 | 做了標記，仍在這台裝置上                             |
| 已清除 | 不在了；你清除所有做了標記的，或早於一段時間的       |

來源收回的 item，不必你開口就會標記為已刪除。它會留著，直到你清除。

清除之後什麼都不留，連 ID 也不留。來源還在提供的 item，下次讀到時會回來。
不想再看到某樣東西，就用規則把它藏起來。

keep 永遠優先：沒有任何清除、任何上限會帶走 keep 的 item。

## item 指向什麼

一個 item 可以用 ID 指向別的 item。它可以指向好幾個，每一個指向都說出自己是哪一種：
這則回覆那則、這則引用那則、這則 reblog 那則。

- reblog 是一個獨立的 item。它有自己的 ID 與自己的時間，也就是 reblog 的時間；
  它被標記為 reblog，並指向它所 reblog 的 item。被 reblog 的 item 站在它自己的發布時間。
- favourite 是 item 上的一個標記，不是 item。
- item 所指向的東西也會被留著。一個 item 第一次抵達、而它所指向的東西不在時，就把那樣東西載入——
  只做一次，而且只載入它直接指向的：被載入的 item 再指向的東西不會跟著去追。
  還沒到之前，它的位置會說它正在路上。
- 被載入的東西之後若被清除，不會再載入一次；指向它的 item 會說它已經不在了。
- 留著的每一樣東西都是普通的 item：不論它是抵達的、被載入的，還是搜尋找到的，
  都跟其他 item 一樣站在自己的發布時間，出現在 timeline 裡。
- reblog 顯示它所 reblog 的東西。問文字的規則也會問那些文字，所以藏住一則貼文的規則也藏住它的 reblog；
  問作者的規則問的是誰做了這個 reblog。

指向只有在打開一個 item 時才會讀，用來顯示跟它在一起的東西。
timeline 不會因為它而把一個 item 收在另一個底下。

## 這台裝置留著什麼

留著的東西是你的。它離開的方式是變成你自己手上的一個檔案，
或在雙方都同意時搬到你的另一部裝置，都不經過我們的任何地方。
你設的上限會放下最舊的，並說出是哪個上限。

## 之後

兩個來源的同一件事是一個 item。今天在兩個來源對它的稱呼一樣時，這已經成立，而且會維持。
一般的情況是下一個 story：在兩個 ID 之間加上連結，兩個 ID 都不改。

## 它不是什麼

- 不是排名器。不評分，也不重排。
- 不是沒有時間的東西的閱讀器。
- 不是繞過來源為了不讓程式讀取所做的任何事的方法。
- 沒有 Fediqo 伺服器。它不存在。
