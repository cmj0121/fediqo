# 圖稿

[English](README.md) | [繁體中文](README.zh-TW.md)

一隻章魚的剪影，浮在機械外殼前面。生物是唯一的主體；牠身後的金屬——銀色面板、暗色切口、
受光的倒角、槍金屬色的底板，以及從上下邊緣切穿的開槽——是章魚出現以前這個標誌的樣子，
留著它，是因為那些開槽還讀得出它從哪條時間軸來。

| 檔案                        | 畫給哪個尺寸                | 差在哪裡                                                         |
| --------------------------- | --------------------------- | ---------------------------------------------------------------- |
| `logo.svg`                  | 64 px 以上                  | 章魚 1.48×，觸手畫得夠細，捲得起來                               |
| `logo-small.svg`            | 32 px 以下                  | 每一道金屬邊界都在 64 單位格線上；章魚 1.30×、粗觸手             |
| `mascot.svg`                | 章魚本身就是主體時          | 同一隻章魚 0.88×，放在圓角底板上，觸手收在裡面                   |
| `kind-mastodon.svg`         | 64 px 以上，當 template     | 圓角方塊、象鼻、m —— 對官方 mark 的剪影，單一 ink               |
| `kind-mastodon-small.svg`   | 32 px 以下，當 template     | 同一剪影，64 單位格線                                            |
| `kind-discuz.svg`           | 64 px 以上，當 template     | 字母 D 與 !，單一 ink                                            |
| `kind-discuz-small.svg`     | 32 px 以下，當 template     | D!，64 單位格線                                                  |
| `source-mastodon.svg`       | 64 px 以上，協定本身是主體  | 同一 mark 放在 mascot 的金屬底板上，邊光與金屬跟章魚同一套       |
| `source-mastodon-small.svg` | 32 px 以下                  | 同一 mark，64 單位格線                                           |
| `source-discuz.svg`         | 64 px 以上，協定本身是主體  | D! 放在 mascot 的金屬底板上                                      |
| `source-discuz-small.svg`   | 32 px 以下                  | D!，64 單位格線                                                  |

1024 單位的畫布畫成 16 px，等於**一個像素 64 單位**。比 64 單位窄的東西會落在像素中間，
反鋸齒把它變成一片灰，所以 `logo-small.svg` 把金屬對齊成
`4 px 面板 | 1 px 切口 | 1 px 倒角 | 10 px 底板`，並且把每根觸手加粗。那裡的章魚畫得比
`logo.svg` **小**而不是大：粗觸手需要空間，而在 16 px，剪影小一點但觸手還在，勝過大一點
但觸手化掉。

有兩個決定值得寫下來，因為兩個都是算圖算出來的，不是推理推出來的：

- **邊光不是裝飾。** 深色剪影放在中灰的金屬上沒有自己的邊界；沒有那圈亮邊，章魚會融進
  底板，到了 16 px 連開槽都融在一起。邊光也是投影可以拿掉的原因——兩者在做同一件事，
  投影輸了。
- **兩張用同一種金屬。** 早先的小尺寸版本把金屬調亮，想幫深色剪影跳出來。結果 32 px 和
  64 px 之間出現看得見的落差，而且根本沒必要：對比已經由邊光扛著，暗一點的金屬襯起來更好。

`mascot.svg` 是卸下了 icon 職責的那隻章魚：icon 的觸手本來就該溢出邊緣，吉祥物的觸手則是
要被看見的。它本身就是圖稿，直接在這裡編輯，不從 `logo.svg` 推導出來。

`kind-*` 是 source row 畫的協定 glyph。一律畫它，不是只在伺服器沒交出自己的圖片時才畫，
理由有兩個。伺服器自己的圖是橫幅：Mastodon 的是寬幅主視覺，Discourse 的通常是橫向字標，
裁成 row 高度的正方形之後只剩中間一條，或是論壇名字中間的兩三個字母；那張圖完整地畫在
顯示單一 source 的 sheet 裡。另一個理由是，row 若去抓它，這份清單會在頁面一打開就連到
上面每一台伺服器——而那正是伺服器目錄被移出這一頁所要避免的事。

它們是 **template**：一種 ink、透明底，所以 row 用 `inkDim`（登入則 `filament`）上色，
不用品牌色。
Mastodon 是這個 repo 自己畫的圓角方塊加象鼻，中間挖一顆 m——不是官方檔案，也不是紫色。
Discuz! 是字母 D 與 !。

`source-*` 是同一組主體，放在 mascot 的金屬底板上，給協定本身就是主體的場合。

這些檔案就是圖稿本身。這裡沒有任何產生出來的東西，也不需要工具去建置——點陣的 app icon
等到真的有 app 可以放的時候，再從 `logo.svg` 與 `logo-small.svg` 算出來。
