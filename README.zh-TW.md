> 你的時間軸，你寫的規則。

Fediqo 是你的時間軸。你加入來源，寫下規則，讀一條依時間排的流。
沒有 Fediqo 伺服器。

## 概念

| 名詞 | 是什麼 | 不是什麼 |
| --- | --- | --- |
| source | 你在讀的伺服器或帳號——協定在它後面 | 不是協定頁 |
| rule | 這條 timeline 讓什麼進來；藏的能指名 | 不是靜音清單 |
| timeline | 對這台裝置上 store 的一條 query | 不是某個網路的首頁 |
| item | 一則 `note` 或一則 `thread` | 不是單一協定的一列 |

## 怎麼運作

```text
  sources (any open protocol)
           │
           ▼
     your device, and nothing else
           │
           ▼
  one shape → merge → your rules → one timeline
```

這條路上的每一件事都發生在你的裝置上。沒有一個 Fediqo 伺服器讓它們經過，而且你不必只聽我們這樣說。

Fediqo 只連到你加入的來源，別的都不連：沒有遙測、沒有當機回報、沒有更新檢查，也沒有第三方。
來源送回來的東西可能指向別處——一張圖片、一個頭像、放在另一台伺服器上的表情符號——那只因為來源指向它才會去抓。
在 app 裡顯示的論壇頁面，不會從別的網站載入任何東西，除非是下面的某一項放行的。
會連到來源以外的，只有這幾個有名字的項目，而且只在你正在做它所為的那件事時：

| 項目 | 什麼時候 |
| --- | --- |
| 來源目錄 | 只在你加入來源、瀏覽可加入的伺服器時 |
| 論壇的瀏覽器檢查 | 在論壇的頁面上 |
| 登入時的真人驗證 | 只在論壇的登入畫面開著時 |
| 從登入頁前往的頁面 | 只在論壇的登入畫面開著時 |

偏好頁的「放行清單」tab 列出它們，說明每一項為什麼在那裡，並讓你關掉任何一項，或為某一個來源加入你自己的主機——例如圖片放在別處的論壇。
關掉一項，它放行的東西從那一刻起就被擋下。這份清單只留你決定的事，從不記下連到了哪裡。

這次執行送出的每一個請求都看得到：偏好頁、「連線中」，再點「這次執行送出的所有請求…」。每一行寫出它是為哪個來源、什麼時候送出、為了什麼——
絕不顯示網址、查詢內容，或任何能以你的身分登入的東西。來源指向的東西列在那個來源底下，某一項放行的會寫出那一項的名字。
清單可以只看一個來源。它只記這次執行：關掉 app 之後，不會留下任何你去過哪裡的紀錄。貼文與它們的圖片是 store，會留著。

要從 app 外面查證，就在它執行時看著它——在 iPhone 上用系統的「App 隱私權報告」，在 Mac 上用任何網路監看工具。
它連到的每一個主機，不是你加入的來源、就是來源指向的東西，或是「放行清單」裡的一項。

store 是你的，可以帶走，也可以放下。它離開的方式有兩種：鎖成一個有密碼的檔案，放在你自己手上；
或在雙方都同意時，搬到你鄰近的另一部裝置——都不經過我們的任何地方，也不經過 Apple 帳號。
其中一部分會在你說好時放下——依一段日期、依一個來源——或在你設的上限到了時放下，而上限放下的東西會說出是哪個上限。
你沒選、你的上限也沒選的東西，一件都不會放下。每一項怎麼運作，寫在下面的「這台裝置留著什麼」。

進去的是好幾個來源，出來的是一條時間軸，所以從兩處讀到的同一則只佔一列，不是兩列。
路上不會有人替它評分或重排：抵達的東西和你看到的東西之間，只有你自己寫的規則。

## 它不是什麼

- 不是把每個網路都接上的競賽
- 不是 RSS、YouTube 與部落格的閱讀器
- 不是 X、Instagram 或 Facebook 的客戶端——只接任何人都能實作、都能自架的協定

## 怎麼做出來的

| 做法       | 意思                                                      |
| ---------- | --------------------------------------------------------- |
| 原生       | Apple 平台上的 Swift----沒有 web view，沒有跨平台 runtime |
| 開放原始碼 | AGPL-3.0，可以從這份 checkout 自己建置，宣稱因此可查證    |

`make test` 跑測試。`make -C Apps run` 打開 macOS app。兩者都不需要這份 checkout 以外的東西。
[`docs/release.md`](docs/release.md) 寫的是那一個需要更多的指令——幫兩個 app 簽名並送到 TestFlight 的那一個。

開 pull request 之前，不論那個 PR 改的是什麼，都要在這台機器上跑完整套件。
那是先把各協定的伺服器帶起來，再解鎖對它們的測試：

```text
make servers
FEDIQO_SERVERS=1 make test
make servers-down
```

`make servers` 需要 Docker。沒有把伺服器帶起來時，單獨跑 `make test` 仍然會過，
而 pull request 檢查的就是那一部分。伺服器、它們解鎖的案例、以及一份 release
建置，會在工作進到 `main` 時跑。

## 怎麼用

空的啟動會打開帳號頁。加入一個 Mastodon 主機或一個 Discuz 論壇當來源——從目錄挑，或自己輸入主機名稱。
它會說出協定的名字；這個工作階段只有這兩種能加入。來源送來的東西進到這台裝置的 store，每一條時間軸都是對那個 store 的 query。
通知與發文在還沒有東西可做之前會停用。

### 發文

從時間軸按 `c` 或發文控制，在這一頁上寫。你從可以發文的來源裡挑一個，以及這則貼文走多遠——用那個來源自己的說法。送出失敗會留下原文。送到的貼文會出現在它該在的時間軸，不必整頁重載。

### 你寫的時間軸

「全部」與「趨勢」是內建的。在它們旁邊，你可以寫自己的。這一列是 `+`、各個時間軸，然後是目前這一條的規則。
Tab 依序走過「全部」、「趨勢」，再照你排的順序走過你的時間軸；`+` 不是一站。
`e` 打開所選時間軸的編輯器；在「全部」或「趨勢」上，它會說這兩條不能編輯。按兩下或長按一個時間軸即可編輯。
要加一條，按 +。
在編輯器裡你可以命名、調整順序、移除一條時間軸，編輯器也會列出它自己的按鍵。
按「完成」才生效；按 Esc 則時間軸維持原樣。你的時間軸留在這台裝置上，重新啟動之後還在。
移除一條時間軸，它的規則會一起移除，貼文還在「全部」裡。

一條時間軸就是它的規則。一條規則指名一種東西：

| 種類 | 讓什麼進來 |
| --- | --- |
| 來源 | 從那個來源來的貼文 |
| 作者 | 那個人（`user@instance`）寫的，或他轉發的貼文 |
| 關鍵字 | 內文含有它的貼文，hashtag 也算 |
| 分類 | 從那個分類來的貼文 |

- 同一種的規則是「任一」：符合其中一條就夠。
- 不同種的規則是「全部」：每一種都得讓它進來。
- 「隱藏」規則會藏起它符合的東西，不管別的規則怎麼放行。只有「隱藏」規則的時間軸，就是「全部」扣掉它藏起來的。
- 作者、關鍵字與分類規則可以對每個來源，也可以只對一個來源。列表與看板屬於某一個來源，所以指名它們的規則只對那個來源。
- 關鍵字不分大小寫、不分全形半形，在內文的任何地方都能符合，不做斷詞。`#swift` 只找 hashtag，也會找到 `#swiftui`；
  `swift` 則連字帶 hashtag 都找。

除了這條時間軸在編輯器裡列給你看的規則，沒有任何東西會把貼文藏起來。一條時間軸沒顯示的每一則，都是被它的某一條規則擋下的，
沒有另外的靜音清單。規則指名的來源或分類如果已經不在，規則會留著，並標成「已不在」。它仍套用在這台裝置留著的貼文上。

時間軸只顯示這台裝置留著的東西。作者規則顯示的是那個人已經來到這裡的貼文，不是他寫過的全部。

### 分類

一則貼文帶著它的來源放它進去的分類。分類是來源自己怎麼切分它送出的東西，你不在 Fediqo 裡建立、改名或刪除分類。

- Mastodon：公開、趨勢、首頁，以及你的每一個列表。
- 論壇：每一個看板。

分類的意思是貼文從那裡來，所以一則貼文可以帶好幾個——例如同時帶首頁與某個列表。登入之前抵達的貼文沒有首頁。
列表是在 Mastodon 伺服器上建立的；列表或看板在那邊改了名，仍是同一個分類，只是換上新名字。
要讀你的哪些列表，在帳號頁那個來源的那一列上選，就像選論壇的看板一樣。登入之後，首頁一定會讀。

### 登入 Mastodon

Mastodon 來源可以在帳號頁它的那一列上登入，這樣才讀得到它的首頁與你的列表。在伺服器自己的頁面打開之前，
Fediqo 會先問你要哪一種登入，並且說清楚哪一部分是哪一部分：只讀，或者讀與寫。讀會把你的首頁與你的列表帶進來。
寫讓你在 Fediqo 裡發文、回覆、轉發、收藏，也可以把它們收回——就這些：Fediqo 從不要求追蹤任何人、改你的個人資料，
或動你的過濾器。選只讀，要求的就正好是 Fediqo 還不能寫的時候要求的那些，所以拒絕寫的那一部分，讀完全不受影響。
要改變你的答案，就再登入一次。

如果你是在 Fediqo 還不能寫的時候登入的，那次登入仍然只會讀，Fediqo 用它什麼也不寫。帳號頁會說明這件事、
點出是哪個來源，並且把選擇就放在旁邊：按一下就會問你同一個問題，不用先登出。在伺服器的頁面上取消，
原本那次登入還是照常在用。你已經同意過的事，絕不會在你背後被放寬。

帳號頁上每一列都會說那個來源上可以做什麼——讀、讀與寫，或者唯讀（那個協定在 Fediqo 裡根本沒有「寫」這件事，
所有論壇都是）。那一列說的是伺服器自己的答案：伺服器給的比 Fediqo 要求的少，就以它給的為準，
那一列說的是可以做什麼，而不是要求了什麼。一個來源擋下了一次寫入，它那一列會說出來，
並且一直說到你再登入它一次為止。

密鑰放在這台裝置的鑰匙圈裡：不在 store 裡，不會複製到 iCloud，
也不會跟著你的 Apple 帳號到另一台裝置。重新啟動之後還在。它到另一台裝置的唯一途徑是你親手開始的：
「帶走」把它裝在上鎖的檔案裡；「搬到鄰近裝置」在雙方都同意時把它送到你的另一部裝置——連同 store，或只搬登入憑證。
兩者都寫在下面的「這台裝置留著什麼」。

在那一列上登出、「清除」與「移除」，都會把密鑰從這台裝置刪掉。首頁與列表已經帶進來的東西，會留到你自己把它丟掉為止。
登入頁不留自己的工作階段，也不與 Safari 共用，所以每次登入都會在伺服器的頁面上問你密碼；登出之後，這台裝置上不會留下任何能以你的身分登入那裡的東西。
伺服器結束了這次登入，來源就顯示為已登出，並且說明；它不會假裝還能用。

論壇登入的 cookie 會留在這台裝置上，直到你登出、「清除」或「移除」；這三個都會拿掉它們，連同你為它存下的密碼。

「移除」一個來源，也會停下 Fediqo 自己會去問它的一切：定時重讀、已經在路上的重新載入、還在排隊的圖片與表情符號，以及從它打開的討論串。直到你再加入它之前，沒有任何東西會再連到它。它的貼文怎麼處理，是你在偏好頁選過一次的事；移除前的提問會說出會是哪一種。

### 讀

| 按鍵 | 做什麼 |
| --- | --- |
| `r` | 重新載入所選時間軸，或打開的那則貼文與它的討論串 |
| `e` | 寫或改所選時間軸 |
| `/` | 搜尋這台裝置上的貼文 |
| `?` | 顯示按鍵清單 |

`r` 只問所選時間軸取材的那些來源。「全部」問每一個來源；「趨勢」問有趨勢的來源，要它們的趨勢；
你寫的時間軸問它的規則指名的來源與分類，對每個來源的規則就問每個來源。打開一則貼文時，`r` 重新載入那則貼文與它的討論串，
不論它來自哪種來源，底下的時間軸則不抓。重新載入還在跑時再按 `r`，不會開第二次；按 Esc 停止它。某個來源失敗會說出來，其他來源照樣進來。
所選的貼文保持選取。

`/` 打開一個搜尋欄。它的樣式會在一則貼文的每一個欄位裡任意位置比對：誰寫的、誰轉發的、內文、hashtag、來源，
以及它帶的分類——用英文或翻譯後的名字，也用列表與看板的名字。`*` 代表任意長度的字（包括零個），`?` 代表剛好一個字。
其他每個字元都代表它自己：沒有 regex、運算子、欄位前綴或引號。大小寫與全形半形不影響找到什麼。
只搜尋這台裝置留著的貼文，不問任何來源。找到的依時間排。清空搜尋欄就回到原本的時間軸。

偏好頁可以設一個最晚日期。之後每一條時間軸——「全部」、「趨勢」、你的，以及搜尋結果——都不顯示那一天 23:59:59
（依這台裝置的時區）之後發佈的貼文，時間軸上也會標明。較新的貼文仍留在這台裝置上；關掉日期就再看到它們，不必重抓。
重新啟動之後，日期還在。

沒有網路時，這台裝置留著的東西照樣讀得到：時間軸、讀過的討論串，以及已經帶進來的圖片。規則照樣能寫、能套用，搜尋也找得到留著的貼文。
需要網路的事——問來源、登入、發文——會說它連不到來源，而不是卡住。網路回來時，先前沒問成的會再問一次，不必重新啟動。

被蓋住的貼文帶一個「已蓋住」標記，和它的文字分開。作者寫了警告的，會讀成作者的警告，和內文分開；沒寫的，
Fediqo 不會替他補一句話。`s` 掀開蓋子，標記改說「原本蓋著」，再按 `s` 會蓋回去。被蓋住的圖片帶同樣的標記。
從討論串按 Esc 回來，打開它的那則貼文會置中，並保持選取。

### 這台裝置留著什麼

用量頁依用途分 tab：來源、時間、保留、副本。Tab 輪換它們。來源放總數、各來源的數字與「清除」；
沒有經過時間軸就留下的貼文——搜尋找到的、對話的回覆、論壇主題的回覆——也算在內，並註明它們是在時間軸之外留著的。
時間放依週或月的分布。保留放兩個上限、「依日期放下」，以及「上限放下了什麼」。
副本放這台裝置留著的圖片，以及捨棄它們的那一項。「清除」會拿掉一個來源的快取副本與登入，但留下它的貼文。
偏好頁放的是你的選擇：語言、主題、字型、最晚日期、移除來源時它的貼文怎麼處理，以及整份 store 離開的兩種方式——「帶走」與「搬到鄰近裝置」。

來源對自己的描述——名字、數字、一則貼文可以多長——跟著來源留在這台裝置上。重新啟動之後，不論有沒有網路，
它的頁面都顯示它上次說的內容與何時說的，並在背後再問一次。有新的說法就取代留著的。

#### 兩個上限

「保留貼文」只留最近幾個月；「空間」是這台裝置給索引與圖片副本合計的大小。兩個並列，先到的那個生效。
超過空間時，先放下圖片副本，最舊的先——再讀到時它們會回來——然後才放下最舊的貼文，每個來源都算。
沒設的上限什麼都不放下，每個來源也都留著。

被上限放下的貼文已不在這裡，所以貼文上無法標明是哪個上限。改由「保留」tab 裡的「上限放下了什麼」來記：
每次上限生效寫一行——哪個上限、何時、放下了幾則貼文或幾個圖片副本、來自哪些來源——從不記貼文本身。
這些行重新啟動之後還在。你自己放下的不會寫在這裡。清除紀錄不會放下任何其他東西。

#### 依日期放下

在「保留」tab 裡。挑第一天與最後一天（都包含，依這台裝置的時區），以及一個來源或全部來源。
放下之前會先問：幾則貼文、來自哪裡，而且它們不會回來；沒說好就什麼都不放下。
之後它們不在任何時間軸、任何搜尋、任何數字裡。那些日子以外的、其他來源的，一件都不動。每個來源都留著。

#### 移除來源的時候

偏好頁放一個選擇：移除來源時，它的貼文跟著不見，或留下。「移除」照這個選擇做、不再問，提問時會說出是哪一種。
留下的貼文標成「來源已移除」，仍在「全部」裡讀得到、搜尋找得到，並和其他貼文一樣放下——依日期，或依上限。
它的登入、圖片與你挑的看板不論哪種都會拿掉，也不會再連到它。

#### 帶走

在偏好頁。「帶走」把這台裝置留著的全部——貼文、時間軸、規則、已讀狀態、來源，以及登入它們的憑證——寫成一個檔案，
用你設的密碼上鎖，放到你選的地方：絕不放在我們的任何地方，也絕不經過 Apple 帳號。
它會先量這裡有多少、問圖片副本要不要一起走，並顯示含圖片與不含圖片各是多大。
含圖片時，這個檔案就是這台裝置沒有網路時顯示的一切；不含時小得多，圖片會在每則貼文再讀到時回來。
密碼至少八個字元，遺失就無法復原：這個檔案能登入每一個來源，所以沒有密碼就什麼都不是，
沒有人——這個 app 不行，別人也不行——能用別的方法打開它。設密碼之前 app 會先這樣告訴你。

「讀回」打開這樣的檔案，問它的密碼，並在任何東西改變之前顯示它裝了什麼——幾則貼文、來自哪些來源、何時帶走的。
在全新安裝或新裝置上，它給出同一份 store，每個來源都照原樣登入。在已經有 store 的裝置上，它會取代那份 store：不合併，提問時會說明。
它會先被證明完整：不是 Fediqo 帶走的檔案、被截斷或被改過的檔案、較新版 Fediqo 寫的檔案，或密碼不對，
各自以自己的理由拒絕，store 原封不動。讀到一半失敗，store 也維持原樣。

不論哪種，都不會有任何東西離開這台裝置。兩者在這次執行的請求裡都列在「這部裝置」之下。

#### 搬到鄰近裝置

在偏好頁，「帶走」底下。你的另一部裝置——手機、平板、Mac，任何配對——可以接收這份 store，中間沒有任何帳號。
「接收鄰近裝置」顯示一組六位數代碼與這台裝置的名字，然後等待。另一部裝置上的「搬到鄰近裝置」列出你正在等待的裝置，
問你選的那部所顯示的代碼，然後顯示一個四字元的標記；接收的裝置在代碼旁顯示同一個標記，
你在任何東西連上之前說兩邊是否一樣。代碼是兩部裝置連線用的金鑰，每次都不同，輸錯只有一次機會：什麼都連不上，接收方會顯示新的代碼。
錯太多次，接收就關閉。

搬的是「帶走」寫的那份——全部連圖片、全部不帶圖片，或只搬登入憑證——封起來，透過 Wi-Fi 或兩部裝置間的直接連線直送另一部裝置，
別的都不經過：不是我們的伺服器、不是 Apple 帳號，也不是只共用同一個 Apple 帳號的裝置。
兩部裝置都會在搬之前先問，任一方都能拒絕，接收方會在任何東西改變之前證明它完整；那裡原有的 store 會被取代，和「讀回」說的一樣。
搬到一半失敗，它維持原樣。雙方都在這次執行的請求裡，把這次搬移列在另一部裝置的名字底下。
第一次時系統會問 Fediqo 是否可以在區域網路找裝置；它只在搬移或接收進行時才找。

重新啟動之後，store 還在。0.2.0 第一次啟動時，會就地把舊的 store 帶過來，不抓任何東西，你也不必做什麼：
每一個來源、貼文、看板、登入與選擇都還在。舊的公開與趨勢貼文帶著那個分類，記下了看板的論壇貼文帶著那個看板。
從論壇跨看板清單來的貼文從沒記下看板，所以不帶分類；來源規則仍找得到它。

比它找到的 store 還舊的版本不會打開它。它會說這是較新版的 Fediqo 寫的，並且原封不動地留著：不讀、不覆寫，也不把它移到一旁。

這份 checkout 還沒有 release tag，正在往 0.7.0 前進。
