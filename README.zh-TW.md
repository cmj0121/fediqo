> 你的時間軸，你寫的規則。

Fediqo 是你的時間軸。你加入來源，寫下規則，讀一條依時間排的流。
沒有 Fediqo 伺服器。

## 概念

| 名詞 | 是什麼 | 不是什麼 |
| --- | --- | --- |
| source | 交得出帶時間的 item、而且能再被問一次的任何來源 | 不是協定頁 |
| item | 帶有發布時間的最小單位 | 不是單一協定的一列 |
| filter | 一條 timeline 讓 item 進來所依的規則；藏的能指名 | 不是靜音清單 |
| timeline | 輸入加一個 filter，依發布時間攤平排開 | 不是某個網路的首頁 |

來源彼此可以要多不像就多不像——某個網路上的帳號、一個論壇、一份 feed、一個分成好幾頁的網頁。
只要它交出的每個 item 都有自己的發布時間（至少到日）、有一個不會變的 ID，而且問得到更新的，它就是 source。
timeline 的輸入是來源，或另一條 timeline；所以新的 timeline 就是一條既有的 timeline 加上一個 filter。

[`docs/concept.zh-TW.md`](docs/concept.zh-TW.md) 是全部：item 與它的 ID、欄位、revision、
你能對 item 做什麼，以及怎麼放下一個 item。

概念是 Fediqo 要去的地方；下面的「怎麼用」是這份 checkout 今天做得到的。
今天可以加入 Mastodon 主機或 Discuz 論壇。貼文自己的 revision 已經有了，timeline 的還沒有。
規則已經可以問 Mastodon 來源自己的欄位，其他種類的來源還沒有宣告任何欄位。
清除之前的已刪除標記，以及建在另一條 timeline 上的 timeline，都還不在這裡。

## 怎麼運作

```text
  sources (anything that gives its items a time)
           │
           ▼
     your device, and nothing else
           │
           ▼
  one shape → merge → your rules → one timeline
```

這條路上的每一件事都發生在你的裝置上。沒有一個 Fediqo 伺服器讓它們經過，而且你不必只聽我們這樣說。

Fediqo 只連到你加入的來源，別的都不連：沒有遙測、沒有當機回報、沒有更新檢查，也沒有第三方。
來源送回來的東西可能指向別處——一張圖片、一個頭像、放在另一台伺服器上的表情符號——那只因為來源指向它才會去抓。
在 app 裡顯示的論壇頁面，不會從別的網站載入任何東西，除非是下面的某一項放行的。
會連到來源以外的，只有這幾個有名字的項目，而且只在你正在做它所為的那件事時：

| 項目 | 什麼時候 |
| --- | --- |
| 來源目錄 | 只在你加入來源、瀏覽可加入的伺服器時 |
| 論壇的瀏覽器檢查 | 在論壇的頁面上 |
| 登入時的真人驗證 | 只在論壇的登入畫面開著時 |
| 從登入頁前往的頁面 | 只在論壇的登入畫面開著時 |

偏好頁的「放行清單」tab 列出它們，說明每一項為什麼在那裡，並讓你關掉任何一項，或為某一個來源加入你自己的主機——例如圖片放在別處的論壇。
關掉一項，它放行的東西從那一刻起就被擋下。這份清單只留你決定的事，從不記下連到了哪裡。

這次執行送出的每一個請求都看得到：偏好頁、「連線中」，再點「這次執行送出的所有請求…」。每一行寫出它是為哪個來源、什麼時候送出、為了什麼——
絕不顯示網址、查詢內容，或任何能以你的身分登入的東西。來源指向的東西列在那個來源底下，某一項放行的會寫出那一項的名字。
清單可以只看一個來源。它只記這次執行：關掉 app 之後，不會留下任何你去過哪裡的紀錄。貼文與它們的圖片是 store，會留著。

要從 app 外面查證，就在它執行時看著它——在 iPhone 上用系統的「App 隱私權報告」，在 Mac 上用任何網路監看工具。
它連到的每一個主機，不是你加入的來源、就是來源指向的東西，或是「放行清單」裡的一項。

store 是你的，可以帶走，也可以放下。它離開的方式有兩種：鎖成一個有密碼的檔案，放在你自己手上；
或在雙方都同意時，搬到你鄰近的另一部裝置——都不經過我們的任何地方，也不經過 Apple 帳號。
其中一部分會在你說好時放下——依一段日期、依一個來源——或在你設的上限到了時放下，而上限放下的東西會說出是哪個上限。
你沒選、你的上限也沒選的東西，一件都不會放下；你留下的貼文，哪一種都不會放下它。每一項怎麼運作，寫在下面的「這台裝置留著什麼」。

進去的是好幾個來源，出來的是一條時間軸，所以從兩處讀到的同一則只佔一列，不是兩列。
路上不會有人替它評分或重排：抵達的東西和你看到的東西之間，只有你自己寫的規則。

## 它不是什麼

- 不是排名器——不評分，也不重排
- 不是沒有時間的東西的閱讀器：書的章節、手冊的頁面
- 不是繞過來源為了不讓程式讀取所做的任何事的方法
- 沒有 Fediqo 伺服器

## 怎麼做出來的

| 做法       | 意思                                                      |
| ---------- | --------------------------------------------------------- |
| 原生       | Apple 平台上的 Swift----沒有 web view，沒有跨平台 runtime |
| 開放原始碼 | AGPL-3.0，可以從這份 checkout 自己建置，宣稱因此可查證    |

`make test` 跑測試。`make -C Apps run` 打開 macOS app。兩者都不需要這份 checkout 以外的東西。
[`docs/release.md`](docs/release.md) 寫的是那一個需要更多的指令——幫兩個 app 簽名並送到 TestFlight 的那一個。

開 pull request 之前，不論那個 PR 改的是什麼，都要在這台機器上跑完整套件。
那是先把各協定的伺服器帶起來，再解鎖對它們的測試：

```text
make servers
FEDIQO_SERVERS=1 make test
make servers-down
```

`make servers` 需要 Docker。沒有把伺服器帶起來時，單獨跑 `make test` 仍然會過，
而 pull request 檢查的就是那一部分。伺服器、它們解鎖的案例、以及一份 release
建置，會在工作進到 `main` 時跑。

Mastodon 伺服器沒有跑 worker，所以它的 seed 會替第一個帳號做出通知，並自己把排隊的工作跑完。
會移除通知的檢查會把通知用掉：兩次 seed 之間夠跑四次，超過的那一次會說要重新 seed，
再跑一次 `make servers` 就補回用掉的。

## 怎麼用

空的啟動會打開帳號頁。加入一個 Mastodon 主機或一個 Discuz 論壇當來源——從目錄挑，或自己輸入主機名稱。
它會說出協定的名字；這個工作階段只有這兩種能加入。來源送來的東西進到這台裝置的 store，每一條時間軸都是對那個 store 的 query。
發文在還沒有東西可做之前會停用；通知隨時都進得去，並會說怎樣才會有東西。

### 發文

從時間軸按 `c` 或發文控制，在這一頁上寫。你從可以發文的來源裡挑一個，以及這則貼文走多遠——用那個來源自己的說法。按下「發佈」，那張表單立刻關上，你留在原來那一頁；在對話裡寫的回覆按「送出」也一樣。
不必等來源。送到的貼文會出現在它該在的時間軸，不必整頁重載。

文字還在送的時候，它是頁面底部的一行——「正在把你的貼文送往」加上它的來源，或「正在把你的回應送往」——哪裡都沒有它的一列：
來源收下之後，貼文才會站進時間軸或對話。那時它自己出現，那一行也跟著不見。
文字在請求送出之前就寫進這台裝置，所以結束程式不會弄丟任何一個字。送往同一個來源的兩則文字，照你寫的順序送到。

沒送到的，會在那一行上照實說出是哪一種，每一個字都留著：

| 那一行說 | 什麼時候 | 它提供 |
| --- | --- | --- |
| 沒有送出 | 請求沒到任何一台能處理它的伺服器，或來源說了不 | 「再送一次」、「編輯」、「丟棄」 |
| 可能已經發佈了 | 其他情況——見下面 | 「再送一次」、「編輯」、「丟棄」 |
| 它等著，或送不出去 | 照現在的情況沒有人能送它——見下面 | 「複製」、「丟棄」 |
| 沒辦法留在這裡 | 它寫不進這台裝置，所以它的請求沒有送出 | 「還是送出」、「複製」、「丟棄」 |
| 沒辦法從這個裝置移除 | 你丟棄了它，或移除了它的來源，而它的文字沒辦法從這台裝置的檔案裡拿掉 | 「丟棄」 |

其他情況是：沒有及時回答、連線斷了、來源或擋在它前面的東西出錯，或文字還在送的時候結束了程式。
沒有人以可寫入的方式登入它的來源、登入的是別人，或它回覆的那則貼文已經不在這裡時，文字會等著，或送不出去。
沒辦法從這個裝置移除的文字不會送出、不能改、也打不開；「丟棄」會再試一次而不再問，之後有一次儲存把它的文字從檔案裡拿掉，那一行就自己不見。

每個視窗顯示的是同一批文字。在一個視窗送出、改過或丟棄的，其他視窗立刻也是；一個視窗正在送的文字，在其他視窗是同樣那一行「正在把你的貼文送往」，沒有東西可按；
一則文字不會同時被兩個視窗送出。

沒有任何東西會自己再送一次，這次執行不會，下一次也不會。可能已經發佈的文字，在讀到那則貼文時會自己離開，而且只說一次。
對這樣的文字按「再送一次」，會先看你在那個來源上最近的貼文。找到了，這則文字就當成已送到而放下。
沒找到、而且離第一次嘗試還不到五十分鐘，它會當成同一個請求再送，認得這個請求的來源不會發佈兩次。
超過之後 Fediqo 會先問，說它可能會發佈兩次，以及該去哪裡看。「編輯」會在這則文字上打開表單；
可能已經發佈的文字改過再送，也會先問，因為它會當成新的一則送出，第一則會留著。
「丟棄」會先問；對可能已經發佈的文字，它會說被忘掉的只有這台裝置上的這一份。

一則文字屬於寫它的那個帳號，絕不會以另一個帳號送出。那個來源登入的是別人時，它會等著，說出兩個帳號，讓你複製或丟棄。
還沒送出的文字，登出和「清除」之後都還在，它那一行會說要以可寫入的方式登入。
它的來源被移除時它們跟著不見，那個提問會數出有幾則。「帶走」與「搬到鄰近裝置」不會帶著它們。

### 你做的事立刻顯示

轉發、收藏與書籤，按下去就畫成已經做了，數字跟著加一，之後才去問來源；把它們收回也一樣。
收回你自己的貼文會先問，說好的那一刻它那一列就從每一份清單離開。來源說好之後，畫面上不會再有別的改變。

最後一按算數。第一按還沒有回答時再按一次，標記會畫成再按過的樣子，不會多送任何東西；
回答到了之後，只有在來源和你現在的意思不一樣時，才會去問相反的那一件。

來源拒絕、連不到，或沒有及時回答時，標記會回到來源最後說的樣子——或那一列回到原來的位置——
並且有一行說出什麼沒有發生、是誰的貼文、在哪個來源、為什麼。

那一行在每一頁底部的一條上，所以不管你之後去了哪一頁都看得到。一行是你做了而沒有發生的一件事，或一則正在送的文字。
沒有時鐘會把一行拿下來。它會留到你把它關閉、同一個動作後來成功了或又失敗一次而取代它，或它的來源被登出、清除或移除為止。
寬的頁面顯示三行，窄的顯示一行；再多就說還有幾則——「還有 2 則」——按下去會在「沒有完成的事」底下全部打開，
那裡的「全部關閉」會把它們都收起來。同一個來源的同一種動作超過三件，會合成一行說有幾件。最多留二十行，只在這次執行裡。
正在送的文字不會被這些收掉：它在送到時離開，或在它自己的「丟棄」時離開。

### 你寫的時間軸

「全部」與「趨勢」是內建的。在它們旁邊，你可以寫自己的。這一列是 `+`、各個時間軸，然後是目前這一條的規則。
Tab 依序走過「全部」、「趨勢」，再照你排的順序走過你的時間軸；`+` 不是一站。
`e` 打開所選時間軸的編輯器；在「全部」或「趨勢」上，它會說這兩條不能編輯。按兩下或長按一個時間軸即可編輯。
要加一條，按 +。
在編輯器裡你可以命名、調整順序、移除一條時間軸，編輯器也會列出它自己的按鍵。
按「完成」才生效；按 Esc 則時間軸維持原樣。你的時間軸留在這台裝置上，重新啟動之後還在。
移除一條時間軸，它的規則會一起移除，貼文還在「全部」裡。

一條時間軸就是它的規則。一條規則指名一種東西：

| 種類 | 讓什麼進來 |
| --- | --- |
| 來源 | 從那個來源來的貼文 |
| 作者 | 那個人（`user@instance`）寫的貼文，以及他做的轉發 |
| 關鍵字 | 內文含有它的貼文，hashtag 也算 |
| 分類 | 從那個分類來的貼文 |
| 欄位 | 來源對它這麼說的貼文——見下面 |

- 同一種的規則是「任一」：符合其中一條就夠。
- 不同種的規則是「全部」：每一種都得讓它進來。每個欄位各自算一種：兩條語言規則是「任一」，一條語言規則加一條「發送對象」規則是「全部」。
- 「隱藏」規則會藏起它符合的東西，不管別的規則怎麼放行。只有「隱藏」規則的時間軸，就是「全部」扣掉它藏起來的。
- 對一個人的規則，問的是他做的——他寫的和他轉發的——顯示和隱藏都一樣。別人轉發的他的貼文，要用第二條規則「轉發誰的貼文」（見下）來藏：
  「隱藏」這位作者，再「隱藏」轉發他的貼文，他的字就哪裡都不會出現。
- 作者、關鍵字與分類規則可以對每個來源，也可以只對一個來源。列表與看板屬於某一個來源，所以指名它們的規則只對那個來源。
- 關鍵字不分大小寫、不分全形半形，在內文的任何地方都能符合，不做斷詞。`#swift` 只找 hashtag，也會找到 `#swiftui`；
  `swift` 則連字帶 hashtag 都找。

除了這條時間軸在編輯器裡列給你看的規則，沒有任何東西會把貼文藏起來。一條時間軸沒顯示的每一則，都是被它的某一條規則擋下的，
沒有另外的靜音清單。規則指名的來源或分類如果已經不在，規則會留著，並標成「已不在」。它仍套用在這台裝置留著的貼文上。

時間軸只顯示這台裝置留著的東西。作者規則顯示的是那個人已經來到這裡的貼文，不是他寫過的全部。

### 只有一種來源會說的事

有些事只有一種來源會對一則貼文說。Mastodon 會說五件，每一件規則都可以問：

| 欄位 | 說的是 | 規則問的是 |
| --- | --- | --- |
| 發送對象 | 這則貼文發送得多遠 | 它的其中一種對象 |
| 語言 | 這則貼文說自己是什麼語言 | 留著的貼文說過的語言 |
| 作者蓋住 | 是否標成敏感或加了警告 | 是，或否 |
| 是轉發 | 這一列是不是某人對一則貼文的轉發 | 是，或否 |
| 轉發誰的貼文 | 轉發所轉發的那則貼文是誰寫的 | 一個人（`user@instance`） |

「是轉發」和「轉發誰的貼文」問的是那一列本身；其他三項問的是貼文，在轉發的那一列上問的就是它轉發的那則貼文。
所以「隱藏」「是轉發：是」會把轉發拿掉，而每則貼文仍站在它自己的位置、只出現一次；只顯示轉發，則不會因為一則貼文被轉發過就顯示它。
在轉發成為一列之前就留著、說自己是因轉發而到來的貼文，是貼文：它的答案是「否」。

只有轉發會說它轉發的是誰的貼文。所以「隱藏」「轉發誰的貼文：`@x@instance`」會藏起別人對那個人貼文的轉發，而留下那個人自己寫的貼文；
「顯示」它則只顯示對他貼文的轉發，不顯示任何貼文。那個人可以自己打，也可以從留著的作者裡挑，和作者規則一樣。
轉發的那則貼文如果這台裝置沒有留著，它在這裡什麼都沒說，這種規則既不顯示它也不藏它；貼文本身、以及論壇來的東西也一樣。

編輯器只在你的來源有宣告這個欄位時才提供它，而且只提供那些來源給得出的值：每一種對象、是與否，
語言則是這台裝置留著的貼文實際說過的語言，用你的語言來稱呼。來源沒說這件事的貼文不會符合：
論壇的貼文沒有「發送對象」，所以這樣的規則既不讓它進來，也不把它藏起來；沒說語言的貼文不符合任何語言規則。
這種規則可以對每個來源，也可以只對一個有宣告這個欄位的來源。最後一個宣告某欄位的來源被移除之後，
規則會留著並標成「已不在」，和指名已不在的東西的任何規則一樣。只由這種規則組成的時間軸，重新載入時只問有宣告該欄位的來源。

### 分類

一則貼文帶著它的來源放它進去的分類。分類是來源自己怎麼切分它送出的東西，你不在 Fediqo 裡建立、改名或刪除分類。

- Mastodon：公開、趨勢、首頁，以及你的每一個列表。
- 論壇：每一個看板。

分類的意思是貼文從那裡來，所以一則貼文可以帶好幾個——例如同時帶首頁與某個列表。登入之前抵達的貼文沒有首頁。
列表是在 Mastodon 伺服器上建立的；列表或看板在那邊改了名，仍是同一個分類，只是換上新名字。
要讀你的哪些列表，在帳號頁那個來源的那一列上選，就像選論壇的看板一樣。登入之後，首頁一定會讀。

### 登入 Mastodon

Mastodon 來源可以在帳號頁它的那一列上登入，這樣才讀得到它的首頁與你的列表。在伺服器自己的頁面打開之前，
Fediqo 會先問你要哪一種登入，並且說清楚哪一部分是哪一部分：只讀，或者讀與寫。讀會把你的首頁與你的列表帶進來。
寫讓你在 Fediqo 裡發文、回覆、轉發、收藏、加書籤，也可以把它們收回——就這些：Fediqo 從不要求追蹤任何人、改你的個人資料，
或動你的過濾器。選只讀，要求的就正好是 Fediqo 還不能寫的時候要求的那些，所以拒絕寫的那一部分，讀完全不受影響。
要改變你的答案，就再登入一次。

如果你是在 Fediqo 還不能寫的時候登入的，那次登入仍然只會讀，Fediqo 用它什麼也不寫。帳號頁上那個來源的那一列會說，
就在它的鑰匙前面：一把鎖和「更新權限」。按一下就會問你同一個問題，不用先登出。在伺服器的頁面上取消，
原本那次登入還是照常在用。你已經同意過的事，絕不會在你背後被放寬。

如果你是在 Fediqo 還不能加書籤的時候登入來讀與寫的，那次登入的發文、回覆、轉發、收藏都和原來一樣；只有書籤還等著。
那裡貼文底下的書籤會說它得先問過，帳號頁也會點出是哪個來源：在任何一處按一下就會問，問的那一頁會寫明書籤，
不用先登出。伺服器沒有書籤可以給的話，你仍然是登入來讀與寫的，那裡的書籤就畫成灰色。

讀取你的通知是另外問的，而且只在你到「通知」頁按下去的時候才問——今天才登入的和很久以前登入的都一樣。
沒有任何登入會自己去要它，帳號頁上也沒有哪一列會因為它多一把鎖。那一按會先問，並且說出伺服器的頁面會被要求的每一件事：
讀取通知；那次登入是讀與寫的話，還有移除通知，因為移除是一個動作；如果那次讀與寫的登入是在 Fediqo 還不能加書籤的時候建立的，
也會加上書籤。在 Fediqo 還不能寫的時候建立的登入，會被問要只讀還是讀與寫，兩個答案都帶著通知。不會把誰登出。
關掉伺服器的頁面，或在上面說不，你原有的登入都照舊。沒有通知可以給的來源，會說它沒有，
在重新開啟 Fediqo 或重新登入它之前不會再問。允許之後，下一次登入那個來源會帶著通知，登出時就忘掉。那次登入自己的提問會說通知跟著一起來——讀取通知，
選了讀與寫的話還有移除通知——不論是再登入一次、加上寫的那一部分，還是問書籤。提問說了什麼，要求的就是什麼：
提問還開著的時候才允許的通知，不會被加進去。

一次登入向它的伺服器要求什麼，用伺服器自己的字：

| 部分 | 要求的 | 什麼時候 |
| --- | --- | --- |
| 讀 | `read:statuses read:lists read:accounts read:search` | 每一次登入 |
| 寫 | `write:statuses write:favourites` | 你選了讀與寫的時候 |
| 書籤 | `write:bookmarks` | 跟著寫 |
| 通知 | `read:notifications` | 只在你到「通知」頁按下去之後 |
| 移除通知 | `write:notifications` | 跟著通知，而且只在那次登入能寫的時候 |

伺服器拒絕 `read:search` 或 `write:bookmarks` 的話，會不帶它再問一次。

書籤是留在來源那邊的。貼文底下的標記說的是它的來源最後說的，上面疊著還在路上的那一按：按下去它就變實心，
沒有送達的那一按會讓它變回去，而且從不寫下來——所以在別的 app 裡、重新啟動之後，看到的都一樣。來源擋下的那一按會說出來，
標記維持原樣；再按一次就是再試一次。「留下」是另一回事，是這台裝置自己的：見下面的「留下一則貼文」。

你剛對一則貼文做的事，不會被一次早就在路上的重新載入蓋回去。時間軸還在載入的時候轉發、收藏或加書籤——或是把它們收回——
那個時間軸到了之後，標記仍然是你按下去的樣子，之後是來源回答那一按的樣子。之後你再要求的重新載入，說的又是來源的話：在別的 app 裡拿掉的標記，
讀起來就是拿掉了。

來源說你轉發過、收藏過、加過書籤的，是你作為那個登入的讀者自己的，登入不在了它們也跟著不在：登出、伺服器結束了那次登入、
「清除」、「移除」，或另一個帳號在那個來源登入之後，它在這裡的貼文對這三件事什麼都不說，直到登入後再讀到時來源再說一次。

帳號頁上一個來源的那一列，在任何寬度都是一行：它的標記、主機名稱、登入的鑰匙，以及三個點。每個來源畫的標記都一樣；
來源沒有的、或現在做不了的，畫成灰色並說明原因。選看板與列表在三個點後面，「清除」與「移除」也是。
那個來源上可以做什麼——讀、讀與寫，或者唯讀（那個協定在 Fediqo 裡根本沒有「寫」這件事，所有論壇都是）——
不再寫在那一列上，VoiceOver 仍然會說。那是伺服器自己的答案：伺服器給的比 Fediqo 要求的少，就以它給的為準，
說的是可以做什麼，而不是要求了什麼。某個登入得再問一次、才能提供它本來做得到的事時，鑰匙前面會有一把鎖和
「更新權限」，和鑰匙在同一行、畫法也一樣；那一列太窄、放不下這幾個字和完整的主機名稱時，只畫那把鎖。
擋下過一次寫入的來源，它是紅的，並且一直留到你再登入它一次為止。

會拿走東西的動作，除了登出以外，都在它所作用的那一列或那一區的三個點後面，而且會先問：來源那一列上的「清除」與「移除」、
用量頁來源明細裡的「清除」與「忘記密碼」、「不再留下」、依日期放下、捨棄圖片副本、
移除一條 timeline 或你加入的主機、收回你自己的貼文、移除一則通知或一個來源的全部通知，以及放下來源擋下的通知。登出是那把鑰匙本身，同樣會先問。
有一個不問的：從正在編輯的 timeline 拿掉一條規則，也在三個點後面，但它只是草稿，按下「完成」之前什麼都不會留下。
丟棄一則沒有送出的文字同樣會先問，從頁面底部它的那一行。

密鑰放在這台裝置的鑰匙圈裡：不在 store 裡，不會複製到 iCloud，
也不會跟著你的 Apple 帳號到另一台裝置。重新啟動之後還在。它到另一台裝置的唯一途徑是你親手開始的：
「帶走」把它裝在上鎖的檔案裡；「搬到鄰近裝置」在雙方都同意時把它送到你的另一部裝置——連同 store，或只搬登入憑證。
兩者都寫在下面的「這台裝置留著什麼」。

登出、「清除」與「移除」，都會把密鑰從這台裝置刪掉。登出是那一列上的鑰匙，而且會先問：問題會說出是哪個來源、什麼會不見，只有在問題裡按下「登出」才會登出。首頁與列表已經帶進來的東西，會留到你自己把它丟掉為止。
登入頁不留自己的工作階段，也不與 Safari 共用，所以每次登入都會在伺服器的頁面上問你密碼；登出之後，這台裝置上不會留下任何能以你的身分登入那裡的東西。
伺服器結束了這次登入，來源就顯示為已登出，並且說明；它不會假裝還能用。

論壇登入的 cookie 會留在這台裝置上，直到你登出、「清除」或「移除」；這三個都會拿掉它們，連同你為它存下的密碼。

「移除」一個來源，也會停下 Fediqo 自己會去問它的一切：定時重讀、已經在路上的重新載入、還在排隊的圖片與表情符號，以及從它打開的討論串。直到你再加入它之前，沒有任何東西會再連到它。它的貼文怎麼處理，是你在偏好頁選過一次的事；移除前的提問會說出會是哪一種。

### 讀

| 按鍵 | 做什麼 |
| --- | --- |
| `r` | 重新載入所選時間軸，或打開的那則貼文與它的討論串 |
| `e` | 寫或改所選時間軸 |
| `/` | 搜尋這台裝置上的貼文 |
| `?` | 顯示按鍵清單 |

`r` 只問所選時間軸取材的那些來源。「全部」問每一個來源；「趨勢」問有趨勢的來源，要它們的趨勢；
你寫的時間軸問它的規則指名的來源與分類，對每個來源的規則就問每個來源。打開一則貼文時，`r` 重新載入那則貼文與它的討論串，
不論它來自哪種來源，底下的時間軸則不抓。重新載入還在跑時再按 `r`，不會開第二次；按 Esc 停止它。某個來源失敗會說出來，其他來源照樣進來。
所選的貼文保持選取。

讀到時間軸的尾端附近，會自動向它的來源要下一段，不必按鍵。在「趨勢」上，那是每個 Mastodon 來源正在上升的貼文的下一段：
進來的貼文帶著趨勢分類，和其他貼文一樣依發佈時間排列——這裡不替它排名。沒有更多可給的來源，會在時間軸的尾端一直寫著，
之後不再問它，直到按 `r` 從頭再讀；中間自動的定時讀取不會改變這件事。失敗的來源會說出來，其他來源照樣進來，之後會再問它。
論壇的趨勢是它的排行榜，沒有下一段。沒有指名要趨勢的時間軸，只沿著時間往下讀。

`/` 打開一個搜尋欄。它的樣式會在一則貼文的每一個欄位裡任意位置比對：誰寫的、誰轉發的、內文、hashtag、來源，
以及它帶的分類——用英文或翻譯後的名字，也用列表與看板的名字。`*` 代表任意長度的字（包括零個），`?` 代表剛好一個字。
其他每個字元都代表它自己：沒有 regex、運算子、欄位前綴或引號。大小寫與全形半形不影響找到什麼。
打字時搜尋的是這台裝置留著的貼文；按 Return 還會去問前面那條時間軸裡可以搜尋的來源。找到的依時間排。清空搜尋欄就回到時間軸。

轉發自己是一列。它的第一行說出是誰轉發的，行尾是轉發的時間——這一列就站在那個時間。下面是貼文本身：作者的頭像與名字，
旁邊是貼文發佈的時間。按轉發的人會打開他的頁面；按頭像或名字會打開作者的頁面。被轉發的貼文自己也站在它發佈的時間，和它不經轉發而來時一樣。
兩列都通過規則的時間軸，兩列都顯示；再讀一次，兩者都不會移動。轉發的那一列顯示這台裝置留著的那則貼文——作者遮住的照樣遮住，來源改過或刪掉的照樣標示——
或說明那則貼文已不再留著，這時那一列就只是轉發本身。來源說已經收回的轉發，會在第一行說出來。
你在那一列上按的，是對那則貼文做的，每個標記也都說明它是送到誰的貼文：收藏、轉發、書籤與回覆都送到那則貼文，打開那一列就是打開那則貼文。
留下那一列，留下的是轉發（留下的標記也這麼說）；只要那則轉發還留著，它顯示的貼文也會一直在，不管別的被放下了什麼——你收回的貼文、或來源說已經不在的貼文也一樣留著，並標示為已從來源消失。對作者的規則問的是誰轉發的，顯示和隱藏都一樣——別人轉發的某個人的貼文，要用「轉發誰的貼文」的規則來藏；對關鍵字或欄位的規則問的是被轉發的貼文，所以藏起一則貼文的規則也藏起它的轉發——只有「是轉發」和「轉發誰的貼文」問的是那一列本身，所以隱藏轉發會留下貼文自己的那一列；
對分類的規則問的是轉發本身，它是經由列出它的那條時間軸來的，而它帶來的貼文不經任何分類。
在轉發成為一列之前就留著、當初因轉發而來的貼文，會留在原處，並說明它是因那個人的轉發而到來，直到某條時間軸再次帶來那次轉發；從那時起，那條時間軸顯示的是轉發那一列，貼文只有在它自己也到來時才由那條時間軸顯示。

一則貼文提到的貼文，會替它讀進來。貼文第一次到來時，如果它回覆的那一則不在這台裝置上——或它引用的那一則沒有一起來——
Fediqo 會向帶來它的那個來源要那一則貼文，不必你開口。到來的貼文會立刻顯示，而說明它回覆誰的那一行、或那個引用，
會說那則貼文還在路上，直到它到了為止。只要一次：再讀到同一則貼文不會再要，讀進來的貼文之後被放下也不會再帶回來。
只讀直接提到的那一則，不會再去讀那一則又提到的。來源說沒有這則的貼文不會再要，那一行會說它在來源已消失或不公開——來源對刪掉的貼文和不讓你看的貼文回答是一樣的；這樣讀進來、之後被放下的貼文，會說它已不再留著；讀取失敗會再試兩次，
之後這次執行就先放著、並在那一列上說明，下次啟動再要。每一次這樣的讀取都和其他的一起列在「這次執行的請求」裡，
只向你自己的來源要——你在那裡登入了就以你的身分，絕不替你改用未登入的方式：登入結束時，你在那裡的時間軸還沒這樣讀完的，會跟著一起放下——而且要排隊：一個來源一次只問一則，
兩則之間至少隔三秒，來源說要慢一點就更慢。一次到來最多向一個來源要十則；其餘的等它們的那一列接近畫面時才讀。
這樣讀進來的貼文和其他貼文一樣，只要提到它的那則貼文還在，它就留著。
引用是照這台裝置留著的那則被引用貼文畫出來的：顯示的是這台裝置最後讀到的內容——那則貼文在來源被改過之後，
要等引用它的貼文或它自己再被讀一次，才會顯示改過的樣子，並留著它先前說的。從這個版本起，引用不再帶著被引用貼文的副本，
所以這台裝置沒有留著的被引用貼文，引用不會再顯示它的字，而是說它已不再留著。

打開一則貼文，會從這台裝置留著的內容裡，顯示和它有關的貼文。上面是它回覆的那一則，以及那一則再回覆的那一則，
一路往上到留著的為止；往上走的時候不會去抓任何東西。再上面那一則如果還在路上、暫時讀不到、在來源已消失或不公開、
或已不再留著，它的位置上會有一行說明。下面是留著的、回覆它的貼文，各自排在它回覆的那一則底下；
再來是留著的、引用它的貼文，有自己的標題。誰轉發了它（以留著的轉發為準），在貼文底下用一行說明。
打開貼文時仍然會向來源讀一次討論串，讀到的內容會顯示，是因為它現在留著、而且回覆了這則貼文——
所以搜尋或時間軸帶來的回覆也會在那裡，沒有網路時看到的就是這台裝置留著的。討論串讀到的回覆，如果它回覆的那一則來源沒有交出來，
會直接排在打開的貼文底下，上面有一行說明那一則目前所知的狀況；這只維持到你結束程式為止，
因為來源把哪些貼文當成同一個討論串交出來並不會寫下來——之後沒有網路時，這樣的回覆在這裡就沒有位置，
要等討論串再讀一次，而它照樣站在「全部」裡。往上也是一樣：從一則回覆打開，而它回覆的那一則來源不給看時，
討論串說站在那一則之上的貼文會先顯示，接著是代替那一則的一行，然後才是這則回覆——同樣只到你結束程式為止。討論串讀到的貼文如果比你要保留的還舊，
會顯示到你結束程式為止，不會留下來。

這台裝置留著的每一則貼文，都站在它的時間軸裡。搜尋帶回來的、在某個 hashtag 底下讀到的、打開一則貼文時讀到的回覆，
以及被另一則貼文引用的貼文，都和其他貼文一樣：各自依發佈時間站在「全部」裡，清空搜尋或關掉那則貼文之後仍然在。
它們都不是經由來源的某個分類進來的，所以規則指名分類的時間軸——例如只由 Home 組成的——不會顯示它們；
對來源、作者、關鍵字或欄位的規則，則會顯示符合的那些。論壇主題的回覆，在你打開主題時讀進來。論壇有標日期的回覆，從此就是一則和其他貼文一樣的貼文：
它站在「全部」裡論壇給它的那個時間——絕不是讀到它的時間——也站在規則放行的時間軸裡，包括對它主題所在看板的規則；
搜尋找得到它；按它會打開它的主題，那則回覆會亮起並出現在畫面裡。論壇沒有給日期的回覆，不在任何時間軸、也不在搜尋裡，
因為除了讀到它的那一刻之外沒有東西能安放它：它仍是主題的一部分，在主題裡讀，也算在留著的總數裡。
只要主題的任何一則回覆還留著，主題就留著。

偏好頁可以設一個最晚日期。之後每一條時間軸——「全部」、「趨勢」、你的，以及搜尋結果——都不顯示那一天 23:59:59
（依這台裝置的時區）之後發佈的貼文，時間軸上也會標明。較新的貼文仍留在這台裝置上；關掉日期就再看到它們，不必重抓。
重新啟動之後，日期還在。

沒有網路時，這台裝置留著的東西照樣讀得到：時間軸、讀過的討論串，以及已經帶進來的圖片。規則照樣能寫、能套用，搜尋也找得到留著的貼文。
需要網路的事——問來源、登入、發文——會說它連不到來源，而不是卡住。網路回來時，先前沒問成的會再問一次，不必重新啟動。

Mastodon 來源說發佈之後修改過的貼文，帶一個「已修改」標記，並且留在原來的位置：它的時間仍是發佈的時間，
沒有任何時間軸會移動它。它顯示的是現在說的，一般的重新載入和打開貼文後按 `r` 都一樣；規則與搜尋問的也是它現在說的。
它之前說的留在這台裝置上——只有這台裝置留過的版本，不會去向來源要——打開貼文時就在它底下，從最舊的開始，
每一個都附上來源說它在何時被修改。第一次讀到時就已經修改過的貼文會有標記，但沒有更早的可看。
一個版本是貼文的文字和作者的警告；之前被蓋住的版本，在你掀開這則貼文的蓋子、或在那個版本上按「掀開」之前仍然蓋著。
在手機上，同時帶有「來源已移除」、「來源已刪除」、「已修改」其中兩個以上標記的貼文，只顯示它們的圖示。
之前的版本算在「用量」裡，帶走與移到附近的裝置時跟著貼文走，貼文不論怎麼被放下，它們都跟著不見；你留下的貼文會留著它們。

被蓋住的貼文帶一個「已蓋住」標記，和它的文字分開。作者寫了警告的，會讀成作者的警告，和內文分開；沒寫的，
Fediqo 不會替他補一句話。`s` 掀開蓋子，標記改說「原本蓋著」，再按 `s` 會蓋回去。被蓋住的圖片帶同樣的標記。
從討論串按 Esc 回來，打開它的那則貼文會置中，並保持選取。

### 通知

通知是你登入的 Mastodon 來源說在那裡發生在你身上的事：有人回覆、提到、轉發、收藏、跟隨、請求跟隨或引用了你；
一個投票結束了；你轉發過的貼文被編輯了；來源自己有話要說。這一頁隨時都進得去。沒有登入任何 Mastodon 時，
它會說怎樣才會有東西；已經登入、但還沒問過通知的來源，會被點名，旁邊按一下就會去問，用的是帳號頁上某個來源得再問一次時畫的同一把鎖——見上面的「登入 Mastodon」。

每個這樣的來源的通知合成一份清單，最新的在上面。每一行說出發生了什麼、是誰做的、和哪一則貼文有關（有的話）、
什麼時候，以及它的來源。來源把同一則貼文的同一種通知收成一行的，就是一行：說出一個人，以及另外還有幾人；
Fediqo 自己不做任何收攏。這個版本還不認得的種類會留著，並說它不認得。

作者蓋住的貼文，在通知的那一行上也是蓋住的，來源擋下的通知也一樣：那一行顯示作者的警告，或說它已蓋住，
絕不顯示底下的字。打開它會到那段對話，在那裡它和在任何地方一樣是蓋住的。

| 按鍵 | 在「通知」做什麼 |
| --- | --- |
| `r` | 重新讀取每個來源的通知 |
| `j` | 往下移；在最後一行，讀更早的 |
| `Return` | 打開你所在的這則通知說的那件事 |
| `p` | 打開你所在的這則通知第一個提到的人 |
| `d` | 移除你所在的這則通知，會先問 |

通知在這一頁打開時、按它的重新讀取標記時、按 `r` 時、往下拉時才讀，絕不照時鐘讀：這一頁關著的時候什麼都不問。
讀取可以停止。往下讀更早的也由你決定——按清單的尾端、在最後一行按 `j`，或用手捲到尾端。
一行通知絕不會排在另一個來源還沒被問到的那一段底下：更早的先留著，等往下讀到那裡才顯示。
失敗的來源會在清單上方被點名，並有再問一次的方法，其他來源照樣進來。

一個來源最多留 2,000 則通知。到了上限，留下的是最新的，只要它還留著那麼多，那個來源就不再往下讀。
這段期間它會在清單上方被點名：它更早的通知不會顯示，而且可能本該排在下面這些之間，因為其他來源還會繼續往下讀。
清單的尾端會說已達上限，而不是說沒有更早的通知了。重新讀取仍然會讀到最新的；等有空位——移除通知，
或保留期限讓舊的離開之後——就會從停下的地方再往下讀。

「保留貼文」留下的月數，通知也適用。比它更舊的通知會被放下，往下讀到那裡就停、不再往更早問，清單的尾端會這樣說。

顯示哪些種類，在這一頁的標頭選，標頭會說略過了幾種。略過種類不會向來源問任何東西，只改變畫出來的，
這個選擇留在這台裝置上。

通知會打開它說的那件事。和貼文有關的，會在時間軸裡打開那則貼文與它的對話，離開之後回到打開它的那一行。
和人有關的——跟隨、跟隨請求——會打開 Fediqo 對那個人顯示的內容。比這台裝置留存的期限還舊的貼文，會在那一行上說明。

移除是在來源那邊做的。一則通知從它那一行的三個點移除，或按 `d`；一個來源的全部通知，從這一頁標頭的三個點一次移除，
一次一個來源。兩者都會先問，而全部移除會拿走那個來源為你留的每一則通知，不論這裡有沒有顯示。
你說好的那一刻那一行就離開，之後才去問來源；來源說好之後，你的其他 app 裡也看不到那則通知。
來源拒絕、失敗或沒有及時回答時，那一行會畫回原來的位置，頁面底部的那一條會說出來並說明原因：
沒有移除成的通知合成一行，說出是哪一則，或說有幾則。登入只讀的來源，移除會畫成灰色並說明原因。

來源說它擋下了它不信任的人送來的通知時，清單上方會有一行說擋下了幾則。打開它，會列出是誰的，
每一個都可以從它的三個點放行或放下，兩者都會先問；提問會先用那個人的位址（`@name@host`）稱呼他，後面才是他自己取的名字。說好的那一刻，那個請求就離開清單；被拒絕或失敗時它會畫回來，並在那一條上說出來。放行也會讓那個人之後的通知直接進來，這是在來源那邊發生的，
Fediqo 無法收回；放行的通知會說正在過來，直到下一次讀取那個來源為止。放下則是在那邊移除它們，不會顯示。
來源沒有擋下任何通知、或根本沒有這回事的，什麼都不畫。

通知留在這台裝置上。一進這一頁就畫出留著的——重新啟動之後也是——並在背後讀取，回答到了清單會自己改變。
通知說的那則貼文跟著它那一行寫下來：它不站在任何時間軸裡，要等你打開它才成為一則和其他貼文一樣的貼文，
那則貼文被放下時也會從那一行離開。來源擋下的通知完全不會寫下來。

一位讀者的通知，登入不在了就跟著不在：登出、「清除」、來源結束了那次登入，或另一個帳號在那個來源登入。
來源被移除時、讀回一份 store 或從鄰近裝置接收一份時，它們也跟著不見。每一種都是從 store 的檔案裡消失，不只是從畫面上消失。
「留下」不適用於通知，「帶走」與「搬到鄰近裝置」也不會帶著通知。

### 在手機上

沒有接鍵盤時，「偏好設定」有一頁「手勢」，列出手指能做的事；接上鍵盤後那一頁就不見了，改由按鍵清單說明。有兩件事仍然只有鍵盤能做：按鍵清單本身，以及重播開場。

窄螢幕只顯示眼前這一條時間軸：它的名稱、用一行寫出的規則，以及用小圓點標出它在你的時間軸裡排第幾。按名稱會列出每一條時間軸，新增一條、修改這一條都在那裡。有分頁的頁面也是同樣的標頭：眼前這個分頁的名稱、每個分頁一個小圓點，按名稱列出全部分頁。
左右滑會到旁邊的那一條，到頭就停；標頭留在原位，動的是它底下的內容。寬螢幕仍然把每個名稱排成一列，一樣可以滑。

永遠有一則貼文被標成正在讀的那一則：畫面上第一則完整顯示的，隨著你捲動而移動，而且不會自己去動列表。被標記的貼文不會被拿來做任何事。
按一下貼文就打開它；貼文下方的記號作用在那一則貼文上；按住一則貼文，會說出是誰寫的、確切的時間、寫給誰看，並列出它的記號能做的事。每一則貼文都以同樣的順序畫同樣的七個記號——回覆、轉發、引用、收藏、書籤、留下，以及三個點——來源不提供的那一個畫成灰色並說明原因。三個點打開的，和按住打開的是同一份清單；收回你自己的貼文只在那裡，而且會先問。
回到一條時間軸時，它停在你離開的地方。

把時間軸往下拉，就重新讀一次。讀的時候，重新載入的記號會變成「停止」。按螢幕最上方回到列表最上面。在打開的貼文、人或標籤上，或某一列的詳細頁上左右滑，就返回；在有分頁的頁面上左右滑，到旁邊的分頁。

在「通知」，按一下通知就打開它說的那件事，把清單往下拉就重新讀取通知。按住一則通知，或按它那一行的三個點，可以移除它。更早的通知，按清單的尾端或捲到那裡就會讀取。

### 這台裝置留著什麼

用量頁依用途分 tab：來源、時間、保留、副本。Tab 輪換它們。來源放總數，以及每個來源一列：它的標記、主機名稱，以及進入明細的入口；明細裡有它的數字——有留著它的通知時，也包括留了幾則——「清除」在明細的三個點後面。每個來源一個貼文數，
從它留下的全部都算在內，論壇主題的回覆也是。
時間放依週或月的分布。保留放兩個上限、「你留下的貼文」、「依日期放下」，以及「上限放下了什麼」。
副本放這台裝置留著的圖片，以及捨棄它們的那一項。「清除」會拿掉一個來源的快取副本與登入，但留下它的貼文。
偏好頁放的是你的選擇：語言、主題、字型、最晚日期、移除來源時它的貼文怎麼處理，以及 store 離開的兩種方式——「帶走」與「搬到鄰近裝置」。

來源對自己的描述——名字、數字、一則貼文可以多長——跟著來源留在這台裝置上。重新啟動之後，不論有沒有網路，
它的頁面都顯示它上次說的內容與何時說的，並在背後再問一次。有新的說法就取代留著的。

你做的任何事都不必等儲存。一按會要求儲存而不等它，連續幾按會一起寫下去；讀取帶進來的東西，
等安靜了一會兒才儲存。這樣的儲存如果寫了貼文，下一次至少隔一分鐘；你按下去要求的儲存仍然立刻寫。
通知和你按下送出的文字各自單獨寫入，不會為了它們重寫貼文，也不等那一分鐘：通知在讀到之後片刻寫入，文字在它的請求送出之前寫入。
離開 app 與結束程式會立刻寫入，所以剛做的事不會遺失；貼文、通知、還沒送出的文字各寫各的，其中一樣寫不進去不會擋住另外兩樣。
有一種按鍵仍然會等：讓東西從這台裝置放下的那一種——依日期、來源已刪除的、把「保留貼文」改短、
登出時來源對它的讀者說過的事、收回一則貼文、對一則通知按「移除」、對沒送出的文字按「丟棄」、「移除」與「清除」。
在它從檔案裡消失之前，不會告訴你它已經不在了。「帶走」與「搬到鄰近裝置」也和原來一樣先寫入。

這種按鍵背後的寫入失敗時，頁面底部會有一行說出是什麼「還沒辦法從這個裝置上清掉。之後會再試一次。」——你移除的通知、你收回的貼文、
你放下的貼文、你移除的來源留在這裡的東西、你清除的東西，或已結束的登入留在這裡的東西。每一種只說一次。
任何一次失敗的儲存都會在一分鐘後自己再試，最多連續五次，之後就等下一次變動或下一次會儲存的按鍵。
那一行在你按它的「關閉」、或有一次儲存寫進去之後不見，不論那次儲存是哪個視窗或哪次重試做的。
依日期放下在那之前也說同一句話，而不說則數。

這台裝置放下的東西，是從它的 store 裡消失，不只是從畫面上消失。一則貼文離開的時候——你放下的、上限放下的、
跟著來源一起走的，或是作者自己收回的——它的字，以及跟它一起留著的舊版文字，會在接下來那次儲存時從 store 的檔案裡被蓋掉；
舊版本留下過這類文字的 store，這個版本第一次打開它時就會清掉。被讀回的檔案取代掉的那一份 store 也不會留著，
因為損壞而被放到一旁的那一份也一樣：在你被告知、取代它的 store 也儲存之後，它就會被刪除。除此之外，
系統在檔案底下留著什麼是系統的事，你先前帶走的檔案也仍然留著它當時留著的東西。

store 打不開的時候，Fediqo 會在你最先看到的地方說出原因，接下來怎麼做則看原因而定。如果 store 只是暫時碰不到——
另一份 Fediqo 正在用它、裝置沒有空間了、它的資料夾讀不到或寫不進去——磁碟上什麼都不會改變，也不會有東西取代它：
Fediqo 這次不帶著它開啟、也不儲存任何東西，所以你這次做的事不會留下來，原因過去之後打開的還是同一份 store。
這樣的一次執行也不會依來源清單清掉任何東西——圖片副本與論壇的登入都維持原樣——會取代 store 的讀回會被拒絕，
帶走也一樣，因為沒有東西可以帶走。如果 store 損壞了，它會被放到一旁，由一份空的取代；通知會這樣說，也會說損壞的那份將被刪除。
你在那則通知上按下「我知道了」、新的 store 也儲存之後它就會被刪除，之後拿不回來。用別的方式把通知放下，或還沒看就結束 Fediqo 的話，
損壞的那份會留著，通知會再出現一次。如果有一次讀回被中斷、留下了兩份 store，Fediqo 兩份都不開，並問你要留哪一份，
同時說出每一份有幾則貼文、最後寫入的時間；另一份要等你選的那一份開啟並儲存之後才會刪除，如果你選的那一份後來發現是損壞的，另一份會被放回來。

#### 留下一則貼文

任何一則貼文都可以留下：按它底下的盒子（在它那一列，或打開它的地方），或在選取的貼文上按 `y`。再按一次就不再留下。
這個標記是這台裝置自己的，不會送任何東西到來源。留下的貼文不會被放下——兩個上限都不會、依日期不會、
放下來源已刪除的貼文時不會、移除它的來源時也不會（不論那個來源的貼文選的是哪一種）：它會留著，標成「來源已移除」。
你自己寫的貼文若已留下，收回之後也還在，標成「來源已刪除」。提問說有幾則貼文會被放下時，留下的不算在內，
「上限放下了什麼」也不會把它算進去。它的圖片副本不會跟著留下：來源被移除時、空間不夠時，它們和其他副本一樣會被放下，
來源還在時再讀到那則貼文就會回來。留下的貼文本身就超過空間時，這裡會一直超過，「空間」會說明；其他貼文一到就會被放下。重新啟動之後它還是留下的，帶走與移到附近的裝置時也跟著走。
不再留下之後，它從那一刻起就是一則普通的貼文：按下去本身不會放下任何東西。

用量頁的「保留」tab 在「你留下的貼文」底下數出你留下了什麼：先是所有來源合計，再依名字逐一列出——你移除的來源也在內——
以及它們的文字有多重，舊版文字也算進去。圖片不在這個數字裡；圖片副本是依來源算的，在「副本」那一頁。
每個數字旁邊三個點後面的「不再留下」，一次把全部、或那個來源的全部都變回不留下。它會先問、說出是幾則，而且不會放下任何東西：
從那之後它們就是一般的貼文，下一次上限生效或下一次放下時可能會帶走它們。兩個來源都帶著的貼文，會透過另一個來源的那一份繼續留著；
單一來源的「不再留下」只數它會變回一般貼文的那些，並說出有幾則還這樣留著，「所有來源」才會全部碰到。會放下貼文的提問——移除來源、
依日期放下——會說有幾則留下的貼文會留著。讀回一份 store、接收或搬移到鄰近裝置時，會在你同意之前說其中幾則是留下的，
而檔案裡的 store 對不上這個數字的話，在這裡有任何改變之前就會被拒絕。舊版本做的沒有寫下這個數字，會說它沒有說。

#### 兩個上限

「保留貼文」只留最近幾個月——連同你留下的貼文，以及仍留著的貼文所引用、或仍留著的轉發所轉發的較舊貼文（它會留在「全部」裡，直到顯示它的那一則走了）；「空間」是這台裝置給索引與圖片副本合計的大小。兩個並列，先到的那個生效。
超過空間時，先放下圖片副本，最舊的先——再讀到時它們會回來——然後才放下最舊的貼文，每個來源都算。
沒設的上限什麼都不放下，每個來源也都留著。

被上限放下的貼文已不在這裡，所以貼文上無法標明是哪個上限。改由「保留」tab 裡的「上限放下了什麼」來記：
每次上限生效寫一行——哪個上限、何時、放下了幾則貼文或幾個圖片副本、來自哪些來源——從不記貼文本身。
這些行重新啟動之後還在。你自己放下的不會寫在這裡。清除紀錄不會放下任何其他東西。

#### 依日期放下

在「保留」tab 裡。挑第一天與最後一天（都包含，依這台裝置的時區），以及一個來源或全部來源。
放下之前會先問：幾則貼文、來自哪裡，而且它們不會回來；沒說好就什麼都不放下。
之後它們不在任何時間軸、任何搜尋、任何數字裡。那些日子以外的、其他來源的，一件都不動。每個來源都留著。

#### 移除來源的時候

偏好頁放一個選擇：移除來源時，它的貼文跟著不見，或留下。「移除」照這個選擇做、不再問，提問時會說出是哪一種。
留下的貼文標成「來源已移除」，仍在「全部」裡讀得到、搜尋找得到，並和其他貼文一樣放下——依日期，或依上限。
它的登入、圖片與你挑的看板不論哪種都會拿掉，也不會再連到它。

#### 帶走

在偏好頁。「帶走」把這台裝置留著的——貼文、時間軸、規則、已讀狀態、來源，以及登入它們的憑證——寫成一個檔案，
用你設的密碼上鎖，放到你選的地方：絕不放在我們的任何地方，也絕不經過 Apple 帳號。
通知，以及還等著送出的文字，不在裡面。
它會先量這裡有多少、問圖片副本要不要一起走，並顯示含圖片與不含圖片各是多大。
含圖片時，這個檔案會照這台裝置沒有網路時顯示的樣子顯示每則貼文；不含時小得多，圖片會在每則貼文再讀到時回來。
密碼至少八個字元，遺失就無法復原：這個檔案能登入每一個來源，所以沒有密碼就什麼都不是，
沒有人——這個 app 不行，別人也不行——能用別的方法打開它。設密碼之前 app 會先這樣告訴你。

「讀回」打開這樣的檔案，問它的密碼，並在任何東西改變之前顯示它裝了什麼——幾則貼文、來自哪些來源、何時帶走的。
在全新安裝或新裝置上，它給出同一份 store，每個來源都照原樣登入。在已經有 store 的裝置上，它會取代那份 store：不合併，提問時會說明。
那裡留著的通知跟著不見；那裡還等著送出的文字會留著。
它會先被證明完整：不是 Fediqo 帶走的檔案、被截斷或被改過的檔案、較新版 Fediqo 寫的檔案，或密碼不對，
各自以自己的理由拒絕，store 原封不動。讀到一半失敗，store 也維持原樣。

不論哪種，都不會有任何東西離開這台裝置。兩者在這次執行的請求裡都列在「這部裝置」之下。

#### 搬到鄰近裝置

在偏好頁，「帶走」底下。你的另一部裝置——手機、平板、Mac，任何配對——可以接收這份 store，中間沒有任何帳號。
「接收鄰近裝置」顯示一組六位數代碼與這台裝置的名字，然後等待。另一部裝置上的「搬到鄰近裝置」列出你正在等待的裝置，
問你選的那部所顯示的代碼，然後顯示一個四字元的標記；接收的裝置在代碼旁顯示同一個標記，
你在任何東西連上之前說兩邊是否一樣。代碼是兩部裝置連線用的金鑰，每次都不同，輸錯只有一次機會：什麼都連不上，接收方會顯示新的代碼。
錯太多次，接收就關閉。

搬的是「帶走」寫的那份——全部連圖片、全部不帶圖片，或只搬登入憑證——封起來，透過 Wi-Fi 或兩部裝置間的直接連線直送另一部裝置，
別的都不經過：不是我們的伺服器、不是 Apple 帳號，也不是只共用同一個 Apple 帳號的裝置。
兩部裝置都會在搬之前先問，任一方都能拒絕，接收方會在任何東西改變之前證明它完整；那裡原有的 store 會被取代，和「讀回」說的一樣。
搬到一半失敗，它維持原樣。雙方都在這次執行的請求裡，把這次搬移列在另一部裝置的名字底下。
第一次時系統會問 Fediqo 是否可以在區域網路找裝置；它只在搬移或接收進行時才找。

重新啟動之後，store 還在。0.2.0 第一次啟動時，會就地把舊的 store 帶過來，不抓任何東西，你也不必做什麼：
每一個來源、貼文、看板、登入與選擇都還在。舊的公開與趨勢貼文帶著那個分類，記下了看板的論壇貼文帶著那個看板。
從論壇跨看板清單來的貼文從沒記下看板，所以不帶分類；來源規則仍找得到它。

比它找到的 store 還舊的版本不會打開它。它會說這是較新版的 Fediqo 寫的，並且原封不動地留著：不讀、不覆寫，也不把它移到一旁。

這份 checkout 還沒有 release tag，正在往 0.7.0 前進。

機械外殼前的一隻章魚。一隻生物同時把手伸進好幾個地方，這就是整個構想；牠身後的金屬留著開槽，

而不是當 icon 的場合，`octopus.svg` 是背後什麼都沒有的那隻章魚。每張為什麼畫成這樣，寫在 [`assets/README.md`](assets/README.md)。
